# bambu-printer-mcp

This file is the repository's shared source of truth for local agents (Claude Code and Codex). Read it before changing or reviewing code. CLAUDE.md and .claude/agents.md defer to these rules.

## Workflow and commits

- This is Rafael's personal fork (`rafaelquintanilha/bambu-printer-mcp`) for his own printers, not a contribution flow. Do not open pull requests, create feature branches, request Codex or GitHub reviews, bump versions, publish to npm, tag releases or deploy the Pages site unless he asks.
- Commit finished work directly to `main` and push it once `npm run build` passes and the relevant tests pass. Run the full `npm test` before pushing changes to src/, native/, scripts/ or tests/. If the checkout is on another branch that other sessions share, fast-forward `main` without switching: `git push origin HEAD:main` and `git fetch . HEAD:main`.
- Fix substantive defects and regressions in the workflows Rafael uses: finding, slicing, uploading, printing, monitoring and controlling the X2D. Note cosmetic objections and speculative hardening for later instead of fixing them.
- Never add AI or agent attribution anywhere in Git or GitHub: no `Co-Authored-By` trailers for Claude, Codex, or other assistants, no "Generated with" footers, and no agent session links in commits, issue comments, or notes.
- Add a present-tense CHANGELOG.md entry under `## Unreleased` for changes to src/, native/, scripts/ or printer behavior.
- When pulling changes from the upstream project (`DMontgomery40/bambu-printer-mcp`), preserve original authorship and the credit in CONTRIBUTORS.md.

## Build and test

- `npm run build` must finish with zero TypeScript errors before committing. Keep tracked dist/ output synchronized with source.
- `node --test tests/behavior.test.mjs` must pass all current tests before pushing. Do not rely on an old fixed test count.
- `npm test` builds and runs the full suite, including printer routing/status, slicer safety, Blender MCP, real npm installation layouts, and desktop packaging. It must pass before pushing code changes to main; CI uses Node.js 24 on Linux.
- Tests use compiled dist/ files, so build before focused test commands. Optional tests against an installed BambuStudio profile tree may skip when that tree or model is unavailable; report those skips separately from failures.
- For installation changes, test the actual tarball in local-hoisted, global, and npm-exec layouts and check the patched dependency at runtime. For desktop changes, inspect and initialize the extracted MCPB archive.
- Do not start physical prints or mutate the user's live Blender scene during routine tests. Use dummy printer credentials, mocked transport boundaries, and isolated headless Blender. Set BAMBU_MODEL explicitly to an empty string in tests of missing-model behavior so dotenv cannot supply a real configuration.

## Architecture and installation

- Bambu-only fork of mcp-3D-printer-server. Do not add OctoPrint, Klipper, Duet, Repetier, Prusa, or Creality printer integrations.
- Keep runtime diagnostics on stderr so stdout carries only MCP protocol messages.
- MCP transports: stdio by default and streamable-http. Printer commands/status use MQTT on port 8883; legacy file operations use FTPS on port 990. X2D internal uploads and model listing use the file-only BambuSource tunnel on port 6000, retaining all-plate inspection and fresh compatibility checks. Confirm upload success only after complete byte-count and checksum readback; never start a job through the file service.
- Use basic-ftp directly for uploads to avoid the bambu-js double-path bug. Use bambu-node directly for project_file commands and correct AMS mapping.
- Keep bambu-node pinned to the version covered by patches/. scripts/install-patches.mjs resolves the dependency actually used by the installed server, validates and applies the bundled patch, supports fully patched reruns, and fails installation on incompatible contents. A guessed local node_modules path or a successful patch-package CLI exit is insufficient proof.
- Patches depend on pinned patch-package internals; changes require fresh-install regressions. Do not silently change unknown printer identities or throw from normal asynchronous status reports.
- Package only intended runtime, source, licenses, and contributor files. Build MCPB in isolated staging without pruning the developer checkout. Never package credentials, local configuration, or private models.
- Use a private OS temporary directory per server instance and distinct generated profile paths for differing content.

## Using the connector with a printer

- Preserve the printer's cloud pairing, Wi-Fi connection and Bambu Handy access. Never switch the printer to LAN Only or Developer Mode to make an integration work.
- Look for saved work before downloading or slicing: `find_saved_prints` with the model name or MakerWorld URL, `get_saved_print_details` for an existing slice, and `list_printer_files` for printer storage. A saved MakerWorld item, an unsliced project, a prepared slice and a file on the printer are different states; do not treat one as another.
- Reuse a prepared slice when it matches the requested model, quantity, scale, plate, nozzles and settings. Slice only when there is no printable G-code, the file is incompatible, or a change was requested, and say why first. Check the resulting process (layer height, filament) against the source project before preparing a review.
- Agree on model, quantity and color before slicing. Uploading and starting a print are separate approvals: an upload request does not authorize printing, and approval for one job never carries over to another.
- Report by evidence. A transfer is done only with its readback receipt; a print has started only when fresh status shows the dispatched `printerJobName` with layers rising, confirmed on camera. A dispatch receipt, a successful login or an uploaded file is not proof of printing.
- When a transfer or start fails, name the failed step and code. Never replay an uncertain upload or print, and do not repeat a failed route without a concrete change that addresses the failure.
- Keep personal accounts, local paths and printer identifiers out of this public repository; they belong in the user's private notes and configuration.

## Printer and slicer safety

- All print routes must inspect the exact dispatched file snapshot and selected plate, enforce independent model/component and declared-material temperature ceilings, and require fresh observed MQTT identity, nozzle configuration, ready state, and actionable-error checks. Configured serial inference and cached display status are not live safety evidence.
- H2C serial prefix `31B` and H2D Pro prefix `239` must agree across displayed status, fresh observed safety identity, and the bundled dependency patch. Retain conflicts as failures.
- A1 serial prefix `039` identifies the full-size A1; `030` identifies A1 mini. Keep status, fresh returned-serial identity, and the bundled parser aligned. Configured model/serial values must never replace fresh observed safety evidence or suppress model conflicts.
- Keep complete physical filament mappings and compare available reported materials. Manual non-RFID material declarations remain supported; do not claim they prove physical spool contents or installed nozzle hardware.
- Remote starts must inspect the actual remote artifact and dispatch an immutable checked copy. Raw bridge methods and option overrides must not bypass the shared gate. Heater-off and stop/cancel controls remain available.

- HMS gating fails closed: only info-level entries and serious/common entries that the printer's serial-prefix table from the pinned Bambu Studio commit lists with empty text may pass. Select that table only from a serial returned in the fresh raw report and matching the observed model; a configured serial alone never qualifies. Apply the same rule to notices and clear exclusions. The print preflight names passed notices and checks log them once per printer. Regenerate `src/safety/hidden-hms.ts` with `scripts/generate-hidden-hms.mjs` from one pinned tag/commit and review the diff, including per-table versions and SHA-256; never pass unlisted, fatal or other prefixes' codes.
- BAMBU_MODEL (or the explicit tool model) is required for every print operation. Elicit it when missing. Never skip validation: G-code for the wrong model can damage hardware.
- Dual-nozzle external trays use 255 for physical nozzle 0 (right/main) and 254 for physical nozzle 1 (left/deputy). Compose inspected selected-plate filament_map with physical_extruder_map before accepting or deriving a spool mapping; require the exact fresh vir_slot entry and preserve explicit mapping with use_ams=false. Encode virtual trays as flat -1 and structured {ams_id: selected tray, slot_id: 0}; retain single-nozzle behavior.
- Physical M104/M109 N selectors on dual-nozzle models do not identify a logical filament. Check their targets against all applicable declared materials. Accept the exact X2D filament-change separator only for X2D; keep H2C record-data separators within its validated startup block.
- Remote orca-slicer-api slicing uses only trusted environment URL/authentication and the selected exact local profile mirror. Preserve recursive profile/BBL validation and independently inspect downloaded bytes and selected plate before printing. Reject unsupported multi-slot/API options explicitly, enforce timeouts, and report that timed-out remote jobs may continue without replaying them.
- X2D file inspection accepts only its official bare `B` material-switch flag and `M620.22 I<declared filament> P1` runout-purge form. Reject numeric flags, extra purge parameters and undeclared positions; preserve independent heater ceilings.
- X2D, H2D and H2D Pro accept OrcaSlicer's `M620.17 T<nozzle> S<target> L-1` preheat for a nozzle without filament, checked against the hardware limit and every declared material. X2D and H2D accept the exact official `M9711` time-lapse capture form (`M0|1`, physical `E`, optional `X/Y` or `U/V` and `Z` inside the machine volume, `S11 C10 O0`, duration `T`). Other models and parameters stay rejected.
- Accept the official A1/A1 mini `M109 H` wait parameter only for those models and only from 0 to 300. Keep `S`/`R` as independently checked heater targets; missing targets, malformed waits, other heater commands, and other models still reject.
- Preserve model-specific upload/command routes and complete positional AMS mappings. Add regressions for the changed model and unaffected routes, including external-spool use where supported.
- H2C vendor startup forms require exactly one executable-start and machine-start-end marker, before actual layer markers or coordinated extrusion. Resolve offset-preheat temperatures by the selected plate header’s `filament_self_index` and `filament_extruder_variant` against the parallel project table; require unique row bindings and temperature agreement, preserving rejection of ambiguous mappings. Check offset-preheat bases and targets, bed `D` targets, and probing heat against independent ceilings; config `layer_change_gcode` settings are not layer markers.
- Native print completion flushes the dispatch receipt and exits the one-shot helper before plug-in teardown. A crash after authorized dispatch is uncertain unless an explicit rejection is reported: warn to check printer status/job name before retrying, and never replay automatically. Dispatch receipt is not physical-print verification.
- Linux X2D emergency MQTT sends need a bounded per-send deadline that revokes dispatch after expiry, including when a pending connection later resolves. Force-close and invalidate an in-flight MQTT publisher on expiry so an offline queued command cannot replay. Let the immediate attempt settle before the counted attempt can reuse its publisher. Keep the wait for older native helpers outside the send deadline, count only the post-helper-exit send, and preserve the independent native result and macOS route.
- X2D status and slicing use its own installed preset. Resolve the model before selecting the optional macOS or Linux native transport. It stores jobs on a ready SD card or USB stick, read from the fresh status as Bambu Studio reads it, and otherwise on internal storage (eMMC). Linux setup installs only the pinned plug-in version and checksums; raise the pin only after `--check-update` reports a matching PrintParams layout. Native printing, upload, heating, resume, and error clearing must retain the shared safety checks. Reject unsupported platforms before slicing or connection, and keep legacy FTPS/remote-file starts blocked. Do not infer physical print success from MQTT status, a successful slice, helper exit status, or mocked routing.
- Resolve both inherits and include dependencies recursively before BambuStudio, Orca, or FULU CLI slicing. Require the exact model/nozzle machine preset from the selected installation; never borrow a missing machine profile from another tree. Preserve configured user directories for custom process/filament dependencies. Missing references, cycles, malformed profiles, or incomplete slot mappings must stop preparation.
- Validate the selected bundled model's BBL/cli_config.json entry. Apply machine_limits when supplied; official P1S/H2D entries may intentionally contain only downward_check. Distinguish a validated no-overlay entry from missing/malformed configuration. The internal flattenForCli sourceProfiles.machine API preserves standalone explicit machine settings. Public Bambu-compatible CLI tools still require the selected model's bundled machine preset: slicer_profile supplies process settings, not a replacement machine configuration, and must not bypass that safety gate.
- Local Orca version-2 BBL caches may supply the exact selected installation's profiles only after bounded framing/CRC/vendor/type validation and with its retained CLI matrix. Keep raw inheritance/includes and cached model metadata, stage generated User identities in a private CLI data directory, and preserve colours/bed/tower positions as project-level arguments. These cache builds retain native extrusion mode for wipe towers; legacy JSON routes keep their existing normalization. Remote API cache mirrors remain unsupported.
- Preserve custom overrides and filament-slot ordering. One explicit filament override replaces every declared project slot; partial positional lists must not silently reuse foreign profiles.
- Prepare one filament colour per slot, preserving explicit colours, project colours, and custom profile values in that order. Apply required colour overlays to standalone custom filament files without replacing their unrelated settings. Preserve an input project's saved prime-tower coordinates unless the caller explicitly overrides them; automatic multi-nozzle placement is only a fallback for an unset position.
- Never swallow inspection or auto-slice failures and upload the original unsliced project. Preserve the actionable error and stop before upload/print dispatch. A .gcode.md5 checksum is not printable G-code.
- Bind dispatched plate paths and checksums to inspected bytes. Reject duplicate/case-colliding ZIP names and inconsistent central/local records before JSZip can collapse them. Printable upload-only requests inspect every plate, verify live model/nozzles, and use unique remote names without overwriting existing files.
- Readiness accepts one terminal state besides IDLE and FINISH: a fresh X2D report with `gcode_state: FAILED`, `print_error: 0`, `fail_reason` `0300400C` (task canceled) and a reported job name or file. Treat it like FINISH: printing requires human bed-clearance confirmation even with `BAMBU_REQUIRE_CONFIRMATION=0`, rechecked for the same job after confirmation and at dispatch. Other failures, other models and active HMS errors stay blocked; send no error-reset command.
- Hardware-error clearing on every model binds approval to the job observed before the prompt and rechecks that job and the codes after acquiring the MQTT connection, before sending.
- Print and positive-heating preflight use human MCP elicitation by default. Only explicit `BAMBU_REQUIRE_CONFIRMATION=0` opts out of ordinary prompts; finished-bed clearance and hardware-error clearing/re-acknowledgment still require human confirmation. Recheck fresh state after a human response. Stop and heater-off never require confirmation.
- The dedicated X2D profile replaces only print elicitation with `prepare_print` and `confirm_print`; `print_3mf` is a preparation alias. Agree on model, quantity and color before slicing, show the exact review, and relay the user's explicit approval. Visually inspect fresh camera evidence for plate clearance; ask for a user check if the image is obstructed or uncertain. This trusted-client attestation may establish clearance remotely, including after FINISH or a canceled job. Never infer consent from silence or reuse approval for another job. Tokens expire and are consumed once; retain file, previous-job, nozzle, plate, selected-spool color/material, error and native dispatch checks. Heating and error clearing keep their existing gates.

## Blender MCP

- Standard Blender integration uses a stdio MCP client configured by trusted BLENDER_MCP_COMMAND and BLENDER_MCP_ARGS. Discover remote tool schemas, validate arguments, preserve MCP content/errors, and propagate addon-disconnected failures.
- Standard edit previews and execution require an explicit new output_path. Legacy-only custom bridge configuration may keep it optional and must not claim output verification.
- Standard STL edits preserve the existing scene, validate the export receipt and finite geometry, and never overwrite an existing output. Keep all processes on a shared local filesystem and require Blender Object Mode.
- Enforce deadlines/cancellation, close child processes, and never automatically replay a mutation. On an interrupted dispatched edit, report that execution may still be running. Test actual PID termination independently of graceful-shutdown logging.
- MCP process discovery does not prove the Blender addon is running; headless tests do not prove a live scene or physical print succeeded. State the evidence accurately.

## Repository hygiene

- `.gitignore` excludes agent scratch plans, progress logs, handoff notes, and draft comments with `*.md`, while explicitly allowing shared AGENTS/CLAUDE rules and public README, CHANGELOG, CONTRIBUTORS, and docs/SLICING documentation. Keep public docs and rules tracked and current; leave private agent notes local. Add an explicit exception for intentional new public documentation.
- Keep real credentials and private artifacts out of Git. Do not print secrets from .env or local configuration.
- The GitHub Pages site in site/ is generated from README.md, docs/, CHANGELOG.md, and CONTRIBUTORS.md; edit those sources, not generated output. Map new or renamed README sections in site/scripts/pages.mjs, keep the home page's model notes in site/scripts/sync-docs.mjs aligned with supported printing, and check documentation changes with `npm --prefix site ci && npm --prefix site run build`.
